## Directory Purposes

**lib/**
- Purpose: Primary application source code folder
- Contains: `*.dart` files
- Key files: `lib/main.dart` - main application entry point

**test/**
- Purpose: Automated tests folder
- Contains: `*_test.dart` test suites
- Key files: `test/widget_test.dart` - checks MyApp widget interactions

**.planning/**
- Purpose: GSD Core state and requirements tracking folder
- Contains: `*.md` state files, `codebase/` folder
- Key files: `PROJECT.md`, `ROADMAP.md`, `REQUIREMENTS.md`, `STATE.md`

## Key File Locations

**Entry Points:**
- `lib/main.dart` - Launch point of the Dart app and MaterialApp config

**Configuration:**
- `pubspec.yaml` - Dependencies, version, assets, and font mappings
- `analysis_options.yaml` - Lint rules and code quality rules

**Core Logic:**
- `lib/main.dart` - MyApp, MyHomePage, and MyHomePageState implementations

**Testing:**
- `test/widget_test.dart` - Verifies correct UI state update upon button press

## Naming Conventions

**Files:**
- snake_case.dart: All Dart source files (e.g., `main.dart`, `widget_test.dart`)
- PascalCase: Dart class names (e.g., `MyApp`, `MyHomePage`, `_MyHomePageState`)

**Directories:**
- snake_case: All directories (e.g., `.planning`, `android`, `ios`)

**Special Patterns:**
- `_test.dart`: Suffixed to files containing tests so the test runner picks them up

## Where to Add New Code

**New Feature (View / Component):**
- Primary code: Create files/folders under `lib/` (e.g., `lib/src/features/` or similar)
- Tests: Create matching files under `test/` (e.g., `test/src/features/`)

**Utilities:**
- Implementation: Create file under `lib/src/utils/`

## Special Directories

**.dart_tool/**
- Purpose: Internal compiler cache and config directory
- Source: Auto-generated by Flutter SDK
- Committed: No (ignored via `.gitignore`)
